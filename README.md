PyPOFacets
==========

Copyright (c) 2018 Universidade Federal Fluminense (UFF).

The PyPOFacets project provides Python implementations of the Radar Cross Section (RCS) simulation. Our implementations are Python translations of the original MATLAB [POFacets](https://www.mathworks.com/matlabcentral/fileexchange/35861-pofacets4-1) implementation.

This is the companion website of the paper *On the Importance of Modularization to the Meaningfulness of Provenance from Scripts* (Journal of Information and Data Management). It contains the scripts, provenance graphs, prompts, and analysis materials used in the paper. All noWorkflow graphs were captured with noWorkflow 2.1.1 on CPython 3.13 and exported with `now export dataflow <trial> -d 1`.

Prompts
-------

* [Prompt used to obtain the LLM-modularized PyPOFacets script](https://github.com/gems-uff/pypofacets/blob/master/prompts/pypofacets_llm_refactoring_prompt.md). The same prompt was given to ChatGPT, Gemini, and GitHub Copilot in February 2026; the Gemini version was selected for the paper (Section 4.5).
* [Prompts of the multi-script evaluation](https://github.com/gems-uff/pypofacets/blob/master/prompts/): demodularization (expert script to monolithic baseline) and remodularization (monolithic baseline to LLM-modularized version), both run with Claude Opus 4.6 through GitHub Copilot Chat in Visual Studio Code (Section 7).

Supplementary LLM round (Section 9, Table 10)
---------------------------------------------

* [llm_supplementary_round/](https://github.com/gems-uff/pypofacets/tree/master/llm_supplementary_round): on 28 October 2026, the prompt above was sent again, once to ChatGPT, Gemini, and GitHub Copilot Chat, and all three outputs were evaluated without selection. The folder records the configuration each interface presented at the time and contains the outputs as generated, the evaluated copies with their two edits (the same as for the Gemini version), and their provenance graphs; the results are in [analysis/results](https://github.com/gems-uff/pypofacets/tree/master/analysis/results) (files `llm_round_*`).

Comparison with the ground truth (Sections 4.6.1 and 4.6.2)
------------------------------------------------------------

* [mappings.xlsx](https://github.com/gems-uff/pypofacets/blob/master/mappings.xlsx): correspondence between the YesWorkflow ground truth (40 data items, 7 port nodes, 14 blocks, data-flow edges) and the names used in each version. Row 10 of sheet Edges was corrected from `ReadArgs -> Time` to `ReadArgs -> OutputDir`, as stated by the YesWorkflow annotation of `output_dir` (line 33 of `yw_monolithic_pypofacets.py`). The sheet Analysis gives the values reported in the revised paper (Table 3 with both components, Figure 8, the edge comparison, and the robustness check), read from [analysis/results](https://github.com/gems-uff/pypofacets/tree/master/analysis/results); the sheet Analysis_2018 keeps the original computation over the graphs of the first submission and is superseded.
* [analysis/](https://github.com/gems-uff/pypofacets/tree/master/analysis): the scripts that compute the comparisons of the paper (`table3_recompute.py`, `edges_compare.py`, `label_match.py`, `compare_functions.py`, `compare_functions_lib.py`, `sim_per_script.py`, `reduced_view.py`) and their outputs in `analysis/results/`:
  * Table 3: `table3.txt` and one trail per version (`table3_<version>.csv`: each ground-truth item, its status and the node that matches it). A node matches an item only when its label equals the item's name (file nodes match by path), one node per item. The manifest of manual matches by final value (`aliases.csv`) is empty: no admissible match was found in the noWorkflow databases of the three versions.
  * Figure 8: the 16 nodes of the monolithic graph determined by this rule (`fig8_monolithic_exact_matches.csv`) and the counts over all nodes of the graph (`figure8_monolithic_universe_all.txt`).
  * Edge comparison: `edges_expert.txt`/`.csv` (95 ground-truth edges, 89 matched, one-to-one, orientation ignored) and `edges_monolithic.txt`/`.csv` (none matched).
  * Functional alignment per script of the multi-script evaluation (Section 7): `sim_per_script.txt`/`.csv`.
  * Robustness check of Section 9: `robustness_table3_variables.txt`.
  * Supplementary LLM round of Section 9 (Table 10): files `llm_round_*` (see [llm_supplementary_round/](https://github.com/gems-uff/pypofacets/tree/master/llm_supplementary_round)).
  Node identifiers (`e_N`, `a_N`) are specific to each execution; the trails refer to the graphs in `output/provenance`.
* [compare_functions.py](https://github.com/gems-uff/pypofacets/blob/master/analysis/compare_functions.py) and [similarity.txt](https://github.com/gems-uff/pypofacets/blob/master/analysis/similarity.txt): the functional-structure equivalence of the first submission (Jaccard similarity over tokenized lines, bidirectional matching); the functional component of Table 3 is now computed by `table3_recompute.py` with the same metric.

Multi-script evaluation (Section 7)
-----------------------------------

* Scripts of the six algorithms (expert, monolithic, and LLM-modularized versions) and the four scripts left for future work: [experiments-jidm repository](https://github.com/claytonchagas/experiments-jidm).
* [multiscript/](https://github.com/gems-uff/pypofacets/tree/master/multiscript): re-execution package with the 18 provenance graphs (`dataflows/*.dot`), the three PyPOFacets graphs, the execution records (`runs.csv`, `environment.txt`), the metrics behind Tables 4, 7, and 8 (`metrics.csv`), and the analysis scripts (`run_all.py`, `graph_metrics.py`, `effect_sizes.py`, `capture_results.py`, `compare_results.py`, `table3_variables.py`).
